- 문서 버전: v0.1 (설계 단계)
- 작성일: 2026-11-02
- 상태: Draft — 구현 전

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 체크하고, 하루가 끝나면 얼마나 해냈는지 확인할 수 있는 가벼운 웹페이지가 필요하다. 회원가입·서버 없이 브라우저만 열면 바로 쓸 수 있어야 한다.

### 1.2 목표
- 오늘 할 일을 3초 안에 추가할 수 있다.
- 완료/미완료 상태와 진행률을 한눈에 볼 수 있다.
- 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.
- 날짜가 바뀌면 "오늘" 목록이 자연스럽게 새로 시작된다.

### 1.3 비목표 (Out of Scope)
- 회원가입/로그인, 서버 저장, 기기 간 동기화
- 팀 공유·협업 기능
- 반복 일정, 알림(푸시), 캘린더 연동
- 모바일 네이티브 앱

## 5. 기술 설계

### 5.1 기술 스택
- **HTML5 + CSS3 + Vanilla JavaScript (ES Modules)**
- 빌드 도구·프레임워크 없음 → `index.html`을 브라우저로 바로 열어 실행
  - 단, ES Module은 `file://`에서 막힐 수 있으므로 개발 시 `npx serve` 등 정적 서버 사용 권장
- 저장소: `localStorage`

> 선택 이유: 기능 규모가 작아 프레임워크 이점이 적고, 배포(GitHub Pages 등)와 유지보수가 가장 단순하다.

### 5.2 폴더 구조 (예정)
```
todolist/
├── prd.md              # 본 문서
├── index.html          # 페이지 마크업
├── css/
│   └── style.css       # 스타일, 디자인 토큰(CSS 변수), 다크 모드
└── js/
    ├── main.js         # 진입점: 초기화, 이벤트 바인딩
    ├── store.js        # 상태 관리 + localStorage 읽기/쓰기
    ├── render.js       # 상태 → DOM 렌더링
    └── date.js         # 날짜 키 생성, 포맷, 자정 감지
```

### 5.3 데이터 모델

```ts
// 할일 1건
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~100자
  done: boolean;
  date: string;        // "YYYY-MM-DD" (로컬 기준, 귀속 날짜)
  priority: "high" | "normal" | "low"; // P1, 기본값 "normal"
  order: number;       // 정렬 순서
  createdAt: number;   // epoch ms
  completedAt: number | null;
  carriedOver: boolean; // 다음 날로 이월된 원본이면 true
}

// localStorage 저장 형태
interface AppData {
  version: 1;          // 스키마 버전 (마이그레이션 대비)
  todos: Todo[];
  settings: {
    theme: "system" | "light" | "dark";
  };
}
```

- 저장 키: `todolist:v1`
- 저장 시점: 상태 변경 직후 전체 `AppData`를 JSON 직렬화하여 저장
- 로드 시: 파싱 실패 또는 `version` 불일치 → 기본값으로 시작하고 원본은 `todolist:backup`에 보관

### 5.4 상태 흐름

```
[사용자 이벤트] → main.js (핸들러)
                    ↓
                store.js (상태 변경 → localStorage 저장)
                    ↓
                render.js (현재 날짜 + 필터 기준으로 목록 다시 그림)
```

- 단방향 흐름: DOM은 상태에서만 파생되며, 이벤트 핸들러는 DOM을 직접 수정하지 않는다.
- 이벤트 위임: 목록 컨테이너(`<ul>`) 하나에 click/dblclick/keydown 리스너를 등록하고 `data-id`로 항목 식별.

### 5.5 주요 모듈 인터페이스 (초안)

| 모듈 | 함수 | 설명 |
|---|---|---|
| store | `load(): AppData` | localStorage에서 읽기 |
| store | `addTodo(text, date)` | 생성 후 저장 |
| store | `toggleTodo(id)` / `updateTodo(id, patch)` / `removeTodo(id)` | CRUD |
| store | `clearCompleted(date)` | 해당 날짜 완료 항목 삭제 |
| store | `getPendingBefore(date): Todo[]` | 이월 후보 조회 |
| store | `carryOver(ids, toDate)` | 이월 처리 |
| render | `render(state, { date, filter })` | 전체 화면 갱신 |
| date | `todayKey(): string` | 로컬 기준 `YYYY-MM-DD` |
| date | `formatKorean(key): string` | `2026년 11월 2일 (월)` |
| date | `onDayChange(cb)` | 1분 간격 확인 + `visibilitychange` 시 확인 |

## 7. 수용 기준 (Acceptance Criteria)

- [ ] 텍스트 입력 후 Enter를 누르면 목록 맨 아래에 추가되고 입력창이 비워진다.
- [ ] 공백만 입력하면 추가되지 않는다.
- [ ] 체크박스를 누르면 완료 표시되고 진행률이 즉시 갱신된다.
- [ ] 새로고침 후에도 할일과 완료 상태가 그대로 남아 있다.
- [ ] 필터 탭에 따라 해당 항목만 표시된다.
- [ ] 다음 날 페이지를 열면 빈 목록이 보이고, 전날 미완료 항목이 있으면 이월 배너가 보인다.
- [ ] `<script>alert(1)</script>`를 입력해도 스크립트가 실행되지 않고 텍스트로 보인다.
- [ ] 360px 폭 화면에서 가로 스크롤이 생기지 않는다.
- [ ] Tab/Enter/Space/Esc만으로 추가·완료·수정·삭제가 가능하다.
